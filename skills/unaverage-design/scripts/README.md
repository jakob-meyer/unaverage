# Scripts

Render, PDF, measurement and check tools. They need Node 22.12 or newer, Python 3 with `pillow` and `numpy`, and an installed Chrome, Chromium, Edge or Brave. They find the browser themselves; otherwise set `CHROME_PATH`.

Once, in the skill folder (the parent of this folder, where `package.json` lives): `npm install` (installs `puppeteer-core` and its dependencies, no browser). The agent offers this command and runs it only after the user's OK ([SKILL.md](../SKILL.md), Environment and tools).

In the references `$S` stands for this folder: set `S=<skill folder>/scripts` once and call the commands from the project folder (`node $S/render.mjs ...`), because mockups and results live there. `$PY` is the Python 3 command found by the tool check: `python3`, else `python`, else `py -3`, each accepted only if `--version` reports Python 3 ([SKILL.md](../SKILL.md), Environment and tools). `generic-check.mjs` finds it through `python.mjs`: first an environment variable `PY`, then the venv `~/.unaverage/venv`, then the commands above; a Python with `pillow` and `numpy` wins. If `$PY -m pip install --user pillow numpy` fails with "externally-managed-environment" (PEP 668), use the venv fallback in [dialogue.md](../references/dialogue.md) 7.1, only after the user's OK.

| Command | Purpose |
|---|---|
| `node $S/render.mjs <file.html\|url> <folder> --viewports 1440x900,390x844 --full [--reduced-motion]` | Screenshots at several widths. With `--fold` the first screen only. Before every capture lazy images load (at most 8 s), and `--full` scrolls through the page once, local files too, so lazy content and scroll reveals are in the picture. `--reduced-motion` emulates `prefers-reduced-motion: reduce` and cuts animations and transitions to their end state, so nothing is captured half faded in. |
| `node $S/render.mjs <file.html> <folder> --selector .slide` | Render every slide, post or screen on its own. The elements need fixed sizes. With `--selector` only the first viewport applies; files are named `<name>-01.png` (without width), so run once per width with its own `--name`. Without `--selector`: `<name>-<width>-fold.png` or `-full.png`. Elements larger than the viewport are cut from one full-page capture, because clip captures beyond the screen can paint large text at the wrong size; an element reaching deeper than 16,384 device pixels is captured on its own with a warning, because Chrome repeats the start of the page in full-page captures from there. Elements inside an inner scroll container (a carousel track, an app shell) are captured on their own, because the full-page capture shows the container in one scroll position only. |
| `node $S/pdf.mjs <file.html\|url> <out.pdf> [--selector .slide] [--size 1920x1080]` | PDF with Chrome: text stays text, fonts are embedded. With `--selector` one page per element at the element's size on screen (1920 x 1080 px prints as 1440 x 810 pt; a print rule of the document that lays an element out at another size is a warning, the page keeps the screen size), no margins, backgrounds and exact colors, every element on a new page; the viewer around the elements drops out (presentation UI, notes, progress bars, transforms, scaling, fixed stages, scroll containers), slides hidden by a presentation mode print too, elements of different sizes get named pages. `--size` lays every element out at that size, for slides sized in `vw` or percent. Without `--selector` the document's own `@page` rules apply (A4 or US Letter, margins); a US Letter PDF without an `@page` size (Chrome's default) is a warning, and so is a paper size (mm, in, A4, letter) in a plain `@page` rule without margin when the document has no `.page` sheets; with `--size`, text cut off at the element box is a warning. Animations end in their end state, lazy images and web fonts are awaited. The output names the page count and page sizes read back from the PDF and warns when the count differs from the elements (or from the `.page` sheets of a document), on text left invisible by build steps or reveal classes, and on a font that did not load. Chrome rounds some page sizes (1080 x 1350 px prints as 1080 x 1350.72 px); the elements are then stretched to the printed size, so no white strip shows at the edge. Variable fonts embed as Type 3 (text stays text and searchable); for a print shop use static font files. |
| `node $S/generic-check.mjs <file.html\|url> --medium web\|ui\|slide\|social\|document [--selector .slide] [--deck talk\|reading] [--allow-fonts "House typeface"] [--brand-colors "#hex"] [--intentional "C13"] --md generic.md` | Generic check v2: 61 tells, 8 clusters, index from red tells plus clusters. 0 to 1 clean, 2 borderline with a visual check, from 3 generic; gate: index at most 2 (ui at most 1) and no cluster. Exempt requirements from brand or brief through `--allow-fonts`, `--brand-colors` and `--intentional` and name them in the wrap-up. Craft (H) is a separate gate. Warns on block, sign-in or error pages and on too little text in the DOM (a whole web page, screen or document under 30 words; a post, slide or, with `--selector`, any surface without a word, a raster image or canvas) and on a selector without a match; then the index or the values of that surface do not apply. Word lists by language (`lang` of the text, else all lists); the skill's own markers count on every page. The report names the detected languages (`lang`) and says `"pixelCheck": "not run"` with the reason when Python, `pillow` or `numpy` is missing. |
| `node $S/measure.mjs <file.html> [--selector .slide] --out measurements.json` | Values: typefaces, type scale, sizes, labels, centering, cards, image area, words in the first screen, contrast violations, and in `safariRisks` the font preloads and blended images that can break a page in Safari. |
| `$PY $S/pixels.py palette <image.png>` | Color shares, saturated pixels, colorfulness, calm area, luminance. |
| `$PY $S/pixels.py sheet <out.png> <images...> --cols 3 --labels` | Contact sheet for sequences and direction mockups. |
| `$PY $S/pixels.py slice <image.png> <folder> [--height 1600] [--max N]` | Split a long screenshot into parts for viewing (`<name>-partNN.jpg`), one after the other without gap or overlap. With `--max N` an image longer than N parts gets N windows spread evenly from top to bottom (the first at the top, the last at the bottom), so a reviewer sees the whole page in a fixed number of images; `skippedPx` in the output names the height left out. |
| `node $S/font-check.mjs --google "Name A,Name B" [--lang de,en]` (or `--css <url> --family "Name"`, `--file <file.woff2> --family "Name"`) | Check a web font for the characters of the output language and for tabular figures, with a negative control. Character sets: `de` (16 characters: umlauts, sharp s, capital sharp s U+1E9E, German quotation marks, euro, ellipsis, minus, narrow no-break space) and `en` (12 characters: curly quotation marks, em dash U+2014, en dash U+2013, ellipsis, minus, pound, euro, multiplication sign, degree); default both. Before every typeface outside the catalog in [fonts.md](../references/fonts.md). |
| `mkdir -p ~/.unaverage && swiftc -O $S/cutout.swift -o ~/.unaverage/cutout` once, then `~/.unaverage/cutout <image> <out.png>` | Cutout with Apple Vision (macOS 14 and newer), PNG with alpha, offline, without a model download. Check the edges at 200%. |
| `$PY $S/shadow.py <subject.png> <out.jpg> --size 1600x1600 --background "#f2f2f0" --light left` | Cut-out subject on a new background with contact and floor shadows (`--cast`, `--contact`, `--choke`, `--fill`). Pillow only. |
| `$PY $S/perspective.py <subject.png> <photo.jpg> "x1,y1 x2,y2 x3,y3 x4,y4" <out.jpg> [--shadow 0.25] [--gloss 0]` | Place a subject in perspective on four corner points in a photo (top left, top right, bottom right, bottom left). Pillow and numpy. |
| `$PY $S/ai_label.py <in> <out.jpg\|.webp\|.png> [--type trainedAlgorithmicMedia]`, `--check <file>` | Write the IPTC digital source type for generated or AI-edited images as XMP and read it back. Does not replace a visible label. |

Helpers: `chrome.mjs` finds the browser, `python.mjs` the Python 3 command.

**File check** (size, mode, weight): `$PY -c "import sys,os;from PIL import Image;[print(f,Image.open(f).size,Image.open(f).mode,os.path.getsize(f)//1024,'KB') for f in sys.argv[1:]]" out/*.png`; RGBA means alpha, remove it with `Image.open(a).convert('RGB').save(b)`.

**Missing tools never fail silently** ([SKILL.md](../SKILL.md), Environment and tools): what drops out without Node, Chrome, Python or Swift, the install commands and the substitutes are in [dialogue.md](../references/dialogue.md) 7.1. The user decides; the wrap-up lists every check that did not run or ran as a substitute.

Calibration of the generic check (2026-10-08, 128 pages, web 1440 x 900): 40 top references and 13 websites awarded in 2025 and 2026 outside the references reach at most index 1; none of the 68 human-designed pages is generic (at most 2, the gate is missed only twice, through a cluster). Of 38 AI pages from v0, Lovable and Bolt, 25 reach index 3 or more and 31 miss the gate; the deliberately generic test pages sit at 9 and 10. Plain AI pages without effects and without a template stack stay clean: the index measures closeness to templates and never replaces the visual check. Slide, social, document and ui are checked only with test files. Recalibrated on 2026-10-16 against the German 2.5.2 on the same day (128 pages, strict and with options): all tells except E1, E3 and E6 and all clusters equal on 131 page pairs apart from measurement noise confirmed by reruns; the new English list entries passed the false-alarm test on the human pages except "coming soon" (E6), which was dropped. Recalibrated on 2026-10-30 against 3.3.0 on the same day (128 pages, strict): only D4 changed, on 6 pages one row fewer, each a step or year row (01 02 03, 1 2 3, 2009 to 2013); no index changed; all other differences were measurement noise of live pages, confirmed by reruns and by alternating runs of both versions.
